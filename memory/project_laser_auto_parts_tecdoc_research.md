## TecDoc — researched, recommended AGAINST for this store

- **What it is:** TecAlliance's TecDoc is the largest European aftermarket parts catalogue (10M+ parts, 800+ manufacturers, 110k+ vehicle types), with its own VIN-decode webservice (a separate license from the base catalogue) that maps a VIN → TecDoc's internal `KTYPE` (vehicle type id) → compatible parts by TecDoc article number.
- **Cost reality:** pricing is not published — every source ("contact us for a quote," bespoke per-phase estimate) confirms it's an enterprise B2B sale, not a self-serve API key. One old data point found: a basic *catalogue-browsing-only* registration was ~€219/year, but that's not the webservice/VIN-decode API this store would need, and real webservice+VIN-decode licensing is understood in the industry to run well into the thousands of EUR/year plus setup, scaled for large multi-branch retailers/wholesalers — not the pricing tier a single-location Growth-plan Saudi store would land in.
- **Why it's a poor fit here regardless of price:** even with a license, TecDoc's article numbers are **not this store's own SKUs** — integrating it means either (a) building a real cross-reference mapping from ~2,000 of this store's own products to TecDoc `KTYPE`/article ids (a large one-time + ongoing data project, harder than the BMW/VW VDS-table research already done by hand), or (b) using it purely as a fitment-checker that never actually links to a buyable product on the site. It also assumes server-side integration effort this store doesn't have (Zid Growth plan, one Google Apps Script proxy is the entire backend) — not impossible, but a materially bigger lift than anything built so far.
- **Track record for this store:** the owner already declined Zid's Professional plan (~18,000 SAR/year, ~$4,800) specifically to avoid a big recurring cost for a fitment/filtering feature (see [[project_laser_auto_parts]], "custom Vitrin theme is DEAD"), and separately declined RapidAPI-style VIN vendors requiring a payment card or an exposed client-side key (see the v3 VIN section in [[project_laser_auto_parts_search_fix]]). TecDoc is a strictly bigger ask on both axes (cost and integration complexity) than either of those declined paths. **Recommendation: don't pursue TecDoc for this store** — flag it to the owner as researched-and-priced-out rather than silently dropping it, but the free/cheap paths below solve the actual stated problem (model decode) far more proportionately.

## Alternatives actually worth considering, cheapest first

1. **Keep + extend the current free stack (recommended first move, $0):** local WMI→brand table + `VDS_TYPE_CODE` Typ-code table (VIN chars 7-8) + the NHTSA `vpic.nhtsa.dot.gov` proxy (via the owner's Google Apps Script, since direct browser `fetch()` to NHTSA is confirmed blocked) is already live and already gets brand+year reliably. The `VDS_TYPE_CODE` table just needs more **independently-verified** entries — same discipline already used (real cited source, e.g. Wikipedia/automobile-catalog/auto-data.net cross-checked, never a guess) — driven off the `*_MISS` tabs in the logging sheet instead of one-off research. This is exactly the same work already in progress per [[project_laser_auto_parts_search_fix]]'s "VDS_TYPE_CODE" section; the honest constraint is BMW has no single clean public Typ-code scheme (varies by generation/body-code), so BMW coverage will stay partial no matter how much of this free path is pursued.
2. **Vincario / vindecoder.eu (recommended paid upgrade if #1's ceiling isn't good enough):** a commercial global VIN-decode API, explicitly marketed with strong **European vehicle** coverage (matches this store's exact brand mix — BMW/Audi/Porsche/VW) and claims ~99.8% accuracy from continuously-updated sources, unlike NHTSA which is a US-regulatory dataset that frequently has an empty `Model` field for GCC/EU-spec VINs. Pricing is transparent and small-business-shaped: **$49/mo for 100 lookups (≡ 49¢ each)**, down to 22¢ each at 5,000/mo, with a 3-lookups/month free tier for testing (no card required). At this store's realistic VIN-search traffic (a homepage widget on a single-shop storefront, not a high-traffic marketplace), the $49/mo tier is very likely more than enough headroom, and is a tiny fraction of the ~$400/mo the declined Zid Professional plan would have cost. **This is the one alternative that could plausibly and directly close the "brand+year but no model" gap** the owner is describing, without the mapping/integration burden TecDoc carries — it plugs into the exact same slot the NHTSA call already occupies (a `fetch()` from the Apps Script proxy, or an additional fallback call after NHTSA returns an empty Model), no other architecture change needed.
3. **PartsLink24 — investigated, not a fit.** Decodes EU VIN → full factory-equipment/options list, but it's built for dealers/listing generation (trim/options/EV specs for used-car listings), not parts-catalogue fitment — wrong shape of data for "which category does this VIN belong to."
4. **DataOne, CarsXE, and similar US-centric VIN API resellers — not investigated in depth**, since they're generally built on the same NHTSA-class US-market data this store's proxy already calls directly for free; no clear reason to pay for a reseller of data already being pulled at no cost, unless one is confirmed to add real non-US coverage NHTSA lacks (not confirmed for any of these).
