Part of [[project_laser_auto_parts]]. Owner asked to surface delivery/pickup info on the product page next to checkout, since it previously only existed on the separate, unlinked-from-product-page `/shipping-and-payment` page.

**Real data already configured natively on this store** (found via the dashboard's own "الشحن والدفع" settings, publicly visible at `/shipping-and-payment`): shipping provider Aramex, coverage nationwide (Riyadh/Al-Kharj/+366 other areas), shipping fee SAR 24, +SAR 10 surcharge for cash-on-delivery. One physical location confirmed as a real, live pickup option (not just internal stock tracking) — Jeddah, Al-Nuzha (location id `f5415e81-1360-49be-b634-5422418d527d`, "AZYAR BRANCH").

**Implementation:** same custom-scripts.js pattern as every other storefront feature here. Finds `.product-details-column` → `.btn-buy-now` → walks up to its buttons-row container → inserts a new info block as the next sibling, right below the Add-to-Cart/Buy-Now buttons. Two lines (🚚 delivery via Aramex + fee, 🏬 branch pickup availability) plus a link to the full `/shipping-and-payment` page. Bilingual via the same `document.documentElement.lang === 'ar'` check used elsewhere (VIN disclaimer, English-name display).

**Styling: reused the theme's own existing utility classes instead of writing custom CSS** — `text-muted-foreground`, `border-border-light`, `text-foreground` (all already used elsewhere on the same page, e.g. the "مشاركة المنتج" share-row divider) — so it's automatically theme-aware (light/dark) with zero custom color code needed. Confirmed the site's own currency-formatting script automatically upgrades a literal "ر.س" string in injected text to the official Saudi Riyal SVG symbol — no special handling needed on this store, it Just Works for any injected Arabic price text.

**Verified live 2026-09-14:** desktop and mobile (390px, no overflow), light and dark mode (link color correctly flips via `text-foreground`, body text stays legible muted-grey in both), and the English text path (sanity-checked directly, same code pattern as the already-proven VIN disclaimer bilingual logic).

**CORRECTED 2026-09-14, same day, within the hour — the original SAR 24 / +SAR 10 figures were WRONG.** Those numbers came from the dashboard's "الشحن والدفع" settings page table, which turned out to be stale/reference values, NOT the real Aramex-calculated cost — owner checked their own real checkout and got SAR 22.50, not 24, and no separate COD surcharge line appeared either. **Lesson: never surface a specific price/fee pulled from a settings/config page as a hardcoded customer-facing number without confirming it against an actual live checkout — shipping costs on this store are calculated dynamically (likely by weight/destination via the real Aramex integration), not a fixed flat rate, so ANY hardcoded SAR figure risks being wrong for some or all orders.**
- **Fix: removed the specific SAR figures entirely** from both language variants. Now reads "شحن عبر أرامكس لجميع مناطق المملكة — تُحتسب رسوم التوصيل عند إتمام الطلب (خلال 1-7 أيام عمل)" / "Delivery via Aramex nationwide — shipping cost calculated at checkout (1-7 business days)" — the "1-7 business days" estimate IS confirmed accurate (visible directly on the real checkout screen the owner shared). The COD-surcharge line was dropped entirely rather than guessing a number for it.
- **The branch-pickup line is unaffected/still accurate** — that's a location fact (Jeddah, Al-Nuzha), not a price, so no similar risk there.
- **If a real, verified flat shipping fee is ever wanted here again**, get it from an actual checkout test (or the Zid order/shipping API, if one exists) — never from the dashboard's own shipping-settings display page again, since that's now confirmed unreliable as a source of the real charged amount on this store.

**RE-CORRECTED same session, minutes later — found the real number and restored it.** Dashboard → اللوجستيات → طرق الشحن (`/services/logistics/shipping-methods`, tab=standard/"شحن عادي") lists every available carrier with its own real configured "سعر البوليصة" (waybill price) — Aramex's own row there shows **22.5 SAR**, exactly matching the owner's real checkout screenshot (22.50 SAR, "1-7 أيام عمل"). This is the correct, verified source — NOT the public `/shipping-and-payment` settings-display page (confirmed unreliable/stale, per the note above) and not a guess. **Final text restored to include the specific number, since it's now independently confirmed by two matching sources:** "التوصيل عبر أرامكس لجميع مناطق المملكة — رسوم التوصيل 22.5 ر.س (خلال 1-7 أيام عمل)" / "Delivery via Aramex nationwide — SAR 22.5 shipping fee (1-7 business days)". Still no COD surcharge number stated (never found a verified one for that specifically).
- **Definitive lesson for this store: the shipping METHODS marketplace page (`/services/logistics/shipping-methods`) is the authoritative source for real per-carrier shipping fees — the separate public-facing `/shipping-and-payment` settings display is NOT reliable and can silently drift out of sync.** Always check the methods-marketplace page (or a real checkout) before stating any shipping price anywhere on this store again.
- **The public `/shipping-and-payment` page itself (still showing stale "24"/"10") — DEPRIORITIZED, owner said leave it 2026-09-14.** Searched for a dashboard field controlling that page's displayed numbers: checked إعدادات الحساب, قيود الشحن والدفع (`/settings/constraints` — empty, that's for conditional shipping/payment RULES, not display content), and the custom Pages app (`/channels/online-store/pages` — no "الشحن والدفع" entry there either). No editable source found; the page appears to auto-generate from the same shipping-methods data (which is already correct) but is showing stale cached values on Zid's own platform side — re-confirmed still stale on a fresh reload. Not an issue with anything in this project's own custom code. If revisited: either wait for it to self-correct, or file it with Zid support directly (their own platform page contradicting their own shipping-methods config).
